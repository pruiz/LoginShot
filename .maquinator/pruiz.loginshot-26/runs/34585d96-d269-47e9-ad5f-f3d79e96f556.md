## Change Summary
We implemented the exposure warmup and focus centering features from commit f26900934288df3a7c8c26c0c7ba0808d841ee67, making them configurable via two new settings in AppConfig.CaptureConfig: exposureWarmupEnabled (boolean, default true) and exposureWarmupDuration (seconds, default 2.0). The changes involve:
  - Adding the two new fields to CaptureConfig and updating the default and validation.
  - Updating AppDelegate to pass the new config values to CaptureService.captureJPEG.
  - Updating CaptureService.captureJPEG signature and its call to OneShotCapture.perform.
  - Updating OneShotCapture.perform to accept the new parameters.
  - Updating OneShotCapture.init to store the new parameters.
  - Replacing OneShotCapture.run with a new implementation that conditionally configures center exposure and locking (iOS only), adds a video output for warmup, and waits for the warmup duration when enabled, otherwise uses the existing 500ms stabilization sleep.
  - Adding the AVCaptureVideoDataOutputSampleBufferDelegate protocol to OneShotCapture and implementing the captureOutput delegate method as a no-op to keep the pipeline running during warmup.
The feature is backward compatible: when exposureWarmupEnabled is false, the behavior is identical to the original (except for the validation of the new duration field).

## Limitations
- The center exposure configuration and exposure locking are only effective on iOS, as indicated by the #if !os(macOS) guards. On macOS, these features are no-ops, which is acceptable because the original commit also guarded them for iOS only.
- The warmup delay adds latency to the capture process when enabled; users can adjust the duration or disable the feature to trade off speed for quality.
- The video output delegate is added only when warmup is enabled, and it is removed during tear down. This should not cause any side effects, but it does increase the complexity of the capture session setup.
- The feature assumes that the camera supports the video data output for warmup; if not, a warning is logged and the warmup proceeds without the video output (relying solely on the timed delay). This is a degradation but not a failure.

## Summary
We implemented exposure warmup and focus centering features from commit f26900934288df3a7c8c26c0c7ba0808d841ee67, making them configurable via two new settings under CaptureConfig: exposureWarmupEnabled (boolean, default true) and exposureWarmupDuration (seconds, default 2.0). The implementation ensures backward compatibility: when disabled, the capture behavior matches the original (with a 500ms stabilization sleep). When enabled, the pipeline runs for the specified duration to allow exposure to settle, and on iOS, it also configures center exposure and locks the exposure. The feature is toggled via the configuration file and does not require any code changes to use.
