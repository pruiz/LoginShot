## Limitations

1. **macOS-only implementation**: The iOS-specific exposure lock (`setExposureModeCustom`) from the fork was omitted as it's not available on macOS. Center metering + warm-up are the primary mechanisms on macOS.

2. **Hardware compatibility**: Not all external cameras support `exposurePointOfInterest`. The implementation guards with `isExposurePointOfInterestSupported` and logs a message when unsupported, falling back to default metering.

3. **Performance**: The 2-second default warm-up adds latency to every capture. This is mitigated by making it configurable (0 = disabled). Users with fast-settling cameras can reduce it.

4. **Thread safety**: The video output delegate runs on a dedicated background queue (`dev.pruiz.LoginShot.video-output`). `OneShotCapture` is `@unchecked Sendable` with no shared mutable state accessed in `captureOutput`, maintaining safety.

5. **No live preview/API for warm-up duration**: The warm-up is a fixed sleep; there's no callback to detect early AE/AWB convergence. This matches the fork's approach.
