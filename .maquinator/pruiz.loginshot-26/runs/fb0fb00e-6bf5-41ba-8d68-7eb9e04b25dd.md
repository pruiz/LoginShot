## Limitations

1. **macOS-only implementation**: The iOS-specific exposure lock (`setExposureModeCustom`) from the fork was omitted as it's not available on macOS. Center metering + warm-up are the primary mechanisms on macOS.

2. **Hardware compatibility**: Not all external cameras support `exposurePointOfInterest`. The implementation guards with `isExposurePointOfInterestSupported` and logs a message when unsupported, falling back to default metering.

3. **Performance**: The 2-second default warm-up adds latency to every capture. This is mitigated by making it configurable (0 = disabled). Users with fast-settling cameras can reduce it.

4. **Thread safety**: The video output delegate runs on a dedicated background queue (`dev.pruiz.LoginShot.video-output`). `OneShotCapture` is `@unchecked Sendable` with no shared mutable state accessed in `captureOutput`, maintaining safety.

5. **No live preview/API for warm-up duration**: The warm-up is a fixed sleep; there's no callback to detect early AE/AWB convergence. This matches the fork's approach.

## Summary

Implemented exposure warm-up and center metering for LoginShot webcam captures with full configurability:

**New configuration options** (under `capture:` in config.yml):
- `exposureWarmUpSeconds: 2` — Seconds to run video pipeline before still capture (0 = disable)
- `centerMeteringEnabled: true` — Use center-weighted exposure metering (point 0.5, 0.5)

**How it works:**
1. When a capture is triggered, the app creates an `AVCaptureSession` with both photo and video outputs
2. If `centerMeteringEnabled`, it sets `exposurePointOfInterest` to frame center and `exposureMode` to `continuousAutoExposure`
3. The session starts, and the video output delegate receives frames (discarded) which forces AE/AWB algorithms to process and converge
4. After `exposureWarmUpSeconds`, a still photo is captured via `AVCapturePhotoOutput`
5. Session is torn down cleanly

**Configuration example:**
```yaml
capture:
  exposureWarmUpSeconds: 3   # longer warm-up for difficult lighting
  centerMeteringEnabled: true
```

**Default behavior** (no config changes needed): 2-second warm-up with center metering enabled, matching the fork's behavior.
