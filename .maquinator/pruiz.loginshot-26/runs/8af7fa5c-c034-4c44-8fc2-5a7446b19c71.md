## Limitations

- **macOS-only center exposure**: The `configureCenterExposure` and `lockExposureAtCurrent` helpers are guarded by `#if !os(macOS)` as in the original zicojiao commit, so focus centering only applies on iOS. On macOS, only the warmup delay (running the video pipeline) takes effect. This is appropriate since macOS AVFoundation doesn't expose the same exposure metering controls.

- **No new unit tests for warmup behavior**: The feedback suggested adding tests for the warmup branches. While the configuration parsing/serialization is covered by existing tests, the OneShotCapture warmup logic itself is not directly unit-tested due to its dependence on AVFoundation hardware. Integration testing would require a physical camera. This is a known gap that could be addressed in follow-up work with a more sophisticated test double.

- **Warmup latency**: When enabled (default), capture latency increases by ~2 seconds (configurable). Users who prioritize speed over exposure quality can disable it via `exposureWarmupEnabled: false` to retain the original 500ms behavior.

## Summary

Implemented exposure warmup and focus centering from zicojiao's commit (f269009) as configurable features in LoginShot.

**What changed:**
- Two new YAML settings under `capture:`:
  - `exposureWarmupEnabled` (bool, default: `true`) — enables warmup pipeline before still capture
  - `exposureWarmupDuration` (float seconds, default: `2.0`) — how long to run warmup

**How it works:**
- When enabled: Adds AVCaptureVideoDataOutput to session, starts session, configures center-weighted exposure metering (iOS only), waits `exposureWarmupDuration` seconds for auto-exposure/white-balance to settle, then captures still image.
- When disabled: Preserves original behavior — brief 500ms stabilization sleep after session start.

**Configuration:**
```yaml
capture:
  exposureWarmupEnabled: true
  exposureWarmupDuration: 2.0
```

**Files changed:** 5 files (CaptureService.swift, ConfigLoader.swift, ConfigWriter.swift, MockCaptureService.swift, README.md)
**Build & tests:** All pass (109 tests, 0 failures)
**Backward compatible:** Yes — disabling warmup restores original capture timing
